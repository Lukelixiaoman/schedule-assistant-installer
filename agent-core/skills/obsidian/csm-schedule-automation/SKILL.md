## Workflow
1. **初始化目录结构**：在 `{obsidian_root}` 下创建 `50_日程/` 目录用于存放每日 `.md` 文件，并在 `90_模板/` 中准备标准日程模板（包含时间、产品线、客户、主题、链接、优先级字段）。
2. **解析与索引构建**：读取 `50_日程/` 下所有 `YYYY-MM-DD.md` 文件，提取结构化事件数据，合并更新至同目录下的 `_index.json` 索引文件，确保包含版本号、时区及完整事件列表。
3. **生成OKKI风格看板**：基于 `_index.json` 数据，在 `{desktop_path}/日程.html` 生成单页应用。采用白底、蓝色主色 (#1677FF)、卡片式布局，支持日/周/月视图切换，并内置数据刷新逻辑以直接读取本地 JSON。
4. **配置定时提醒**：根据 `{event_time}` 和 `{reminder_offset}`（如前15分钟），使用 cron 工具创建定时任务，触发 `notify_user` 推送包含客户名称、培训主题及会议链接的通知。
5. **验证链路完整性**：创建一条示例日程，确认其正确写入 Markdown、同步至 JSON 索引、在看板中可见，并成功注册 cron 任务。

## Suggestions
- 建议在 Obsidian 中使用 Templater 插件配合 `90_模板/日程模板.md` 快速录入，减少手动格式错误。
- 看板 HTML 文件可直接通过浏览器打开，无需本地服务器，方便随时查看。
- 对于重要客户（如运营总监出席），建议在 Markdown 中标记“重要”，在看板中以特殊颜色高亮显示。

## Fallback / Edge Cases
- 若 `_index.json` 解析失败，检查 Markdown 文件格式是否符合 `- [ ] HH:MM-HH:MM | ...` 的标准分隔符规范。
- 若 cron 任务未触发，检查系统时间与时区设置是否与 Agent 配置的 `Asia/Shanghai` 一致。

## Pitfalls
- 步骤 2：避免将根目录下的同名日记文件（如 `2026-07-10.md`）误纳入日程索引，必须严格限定在 `50_日程/` 子目录内操作。
- 步骤 3：生成 HTML 时需硬编码或动态获取正确的本地文件路径，确保浏览器能跨域或本地加载 JSON 数据（建议使用内嵌数据或 CORS 友好的本地服务方式）。
